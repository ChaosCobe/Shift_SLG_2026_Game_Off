## 项目体验与总体原则

### 当前核心体验

《SHIFT》当前以**交互体验**为核心，而非以经营调度为第一目标。玩家在相互关联的表世界与里世界中，与NPC、设施及环境交互；面对目标明确的委托，主动寻找解决路径，并观察行为对两个世界、NPC和后续事件产生的结果。

- **问题明确，解法开放：** 正式委托直接交代目标；玩法重点是“如何解决”，不是反复猜测委托人真正想要什么。
- **自由探索与切换：** 世界切换是基础交互手段，不按次数施加混沌惩罚。
- **行动影响世界：** 世界状态由实际行为与预设事件改变，不以任务界面中的“选择方案”替代实际操作。
- **不同后果都推动进程：** 必做任务既可能成功，也可能失败；失败与否和解决途径都可以引出新的事件线。
- **减少无意义的流程负担：** 不统一设置任务验证小游戏、强制推理题或实时时间压力。

### 四个系统的职责划分

| 系统 | 主要职责 | 不负责的内容 |
|---|---|---|
| SYS-001 双世界系统 | 当前世界、SHIFT、位置映射、环境状态与跨世界联动 | NPC对话内容、任务目标判定、混沌数值结算细节 |
| SYS-002 NPC与接待系统 | 同一NPC的双身份、对话、来访与接待 | 正式委托的状态机与完成条件 |
| SYS-003 任务与委托系统 | 正式委托发布/接取、动态条件、成功/失败结算及奖励反馈 | 天气或设施操作本身的执行 |
| SYS-005 每日流程与事件系统 | 日初安排、日期推进、预设事件解锁与并行待处理 | 设施小玩法的具体规则 |

## SYS-001 双世界系统

### 世界基础设定【已确认】

- 游戏存在**表世界**与**里世界**两个具有自然对应关系的平行世界。
- 表世界以蒸汽维多利亚、机械与科学技术为基础，直接改变自然环境的能力受限；里世界以魔法、术式为基础，可以较直接地干预自然条件。
- 玩家在表世界的主要身份是空港管理员；在里世界是传送法阵的管理/修复负责人。
- 两世界部分自然环境存在联动可能性，例如在里世界改变对应区域天气，可以影响表世界的天气。
- 这种关系属于基础世界观规则，**无须额外设计空间锚定等复杂伪科学解释**。

### 世界切换【已确认】

**DW-001｜SHIFT 自由切换**

- 玩家原则上可以随时通过 SHIFT 切换表/里世界。
- **切换本身不产生混沌值变化。**
- 世界切换后显示目标世界的场景、NPC形象及可交互内容。
- 玩家切离某世界，不会让该世界已经发生的状态变化失效。

**DW-014｜位置对应**

- SHIFT 后玩家出现在另一世界的**对应位置**，而不是目标世界上次离开的位置。
- **地图设计硬约束：** 所有允许 SHIFT 的位置，在另一世界对应位置都必须能合法落脚；双世界地图设计应保证可切换区域的对应可通行性。
- 不以“附近寻找落脚点”“切换失败”“强制传送到其他地点”等机制替代地图设计约束。
- 地图验收须进行双向 SHIFT 通行检查；位置不可用属于需要修复的场景问题。

### 特殊交互状态下的 SHIFT【已确认】

| 当前玩家状态 | SHIFT 处理规则 |
|---|---|
| 聚落与普通探索场景 | 自由切换至对应世界、对应位置 |
| 设施场景（尚未进入小玩法） | 可以 SHIFT，切换至目标世界对应设施场景 |
| 设施的小玩法操作界面 | **隐藏并禁用 SHIFT 入口**；退出/完成小玩法返回设施场景后恢复 |
| NPC对话进行中 | 弹出不建议切换的体验提示；取消则保持原状，确认则切换场景和NPC立绘，但**当前对话文本、分支、进度不变** |

补充约束：若 SHIFT 既有UI按钮又有快捷键，进入小玩法时不能只隐藏图标而保留快捷键的有效切换行为。对话中SHIFT的特殊彩蛋属于**后期可选打磨**，不纳入首版必需功能。

###  环境状态与联动【已确认】

**DW-006｜预设事件驱动联动**

- 两世界自然环境有对应关系，**但不要求所有天气等状态始终自动同步**。
- 当环境事件发生时，系统检查该事件是否配置了跨世界影响；仅将**明确配置**的环境效果传递到目标世界。
- 世界联动不需要等待玩家切回目标世界后才执行。
- 跨世界影响与混沌增长是相互独立的事件效果：可同时发生，也可能只发生其中一种。
- 一次跨世界状态更新不得反向递归触发自身，造成循环传播。

**DW-007｜按事件配置环境效果持续规则**

| 持续类型 | 规则 |
|---|---|
| 持续生效型 | 持续存在，直到被后续事件或规则修改 |
| 限时型 | 依据该事件配置的期限结束 |
| 事件绑定型 | 指定任务/剧情事件发生或结束时解除、恢复 |

游戏已确认**无实时流逝的日内时钟**，因此限时效果的具体计量方式需要与日期或离散事件进度相适配；具体单位仍待确定。

**DW-013｜环境效果冲突**

- 对同一世界、同一区域、同一环境属性，**新效果覆盖旧效果**。
- 被覆盖的旧临时效果终止，后续不会重新生效。
- 新临时效果结束后恢复该属性的**基础环境状态**，而不是恢复旧临时效果。
- 长期性环境改变可以修改基础环境状态；临时效果可以覆盖基础状态。（数据组织属实现建议。）
- 覆盖环境效果不会撤销此前已产生的混沌变化。

### 混沌触发边界【已确认】

- 混沌值由**策划预设的、对另一世界造成显著影响的关键行为/事件**触发。
- 不使用实时分析影响范围/程度的复杂模拟算法。
- 例：玩家在里世界执行改变天气的关键魔法，按事件配置增加混沌；只是进出世界、观察天气或普通探索并不因此增加混沌。
- 混沌在关键行为真正发生时结算，而非等到接取任务或交付任务时补算。
- 同一事件不得因系统重复检查或推进多个委托而意外重复增加混沌。
- 混沌具体增量、后续奖励/风险及世界交融效果**不在本稿确定**。

###  SYS-001 仍待确认

- 环境限时效果的具体计量单位、跨日期更新时点。
- 环境联动属性的正式清单，以及各事件的具体对应关系。

##  SYS-002 NPC双身份与接待系统

### NPC双身份【已确认】

- **所有可交互NPC均采用“一体两面”设计**：同一NPC在两个世界是同一实体，共用唯一NPC ID。
- NPC的人物关系、记忆和身份连续性跨世界保持；职业、社会身份、需求、立绘、对话可以因世界而异。

### NPC对话【已确认】

- 基础对话支持姓名、立绘、对话文本、选项，以及依照NPC/世界/剧情状态选择内容。
- NPC交互不以复杂的“猜测真实需求”作为通用玩法。正式委托目标直接说明，推理只保留于少数确有价值的特殊内容。
- 对话中SHIFT使用SYS-001的警告确认规则：确认后切场景和立绘，但继续当前文本及对话进度，不切换到另一套对话分支。
- NPC接待不必每次都发布任务，也可以是人物交流、背景信息或已有任务的反馈。

###  来访与接待【已确认】

- 表世界**空港站房**是主要NPC接待场所。
- NPC来访采取**计划来访 + 少量临时来访**的混合方式；每天开始时玩家能预先了解大部分计划来访安排。
- **普通临时来访：** 满足预设条件后加入待接待名单，玩家选择何时接待；不强制打断当前操作。
- **重要人物/剧情事件：** 满足触发条件后开放相应交互入口，玩家主动访问后进入剧情，不默认强制播放或打断当前交互。
- 接待流程可包含：来访信息→玩家进入接待→对话及需求/委托信息→人物/任务/事件状态更新。具体NPC内容可以不同，不要求固定问询阶段或推理答题。
- 正式委托**仅在表世界查看、主动接取与正式交付**；里世界的人物互动不因此承担正式委托接取与交付。

###  SYS-002 仍待确认

- 计划来访NPC何时正式进入待接待状态；普通访客的等待/离开条件。
- NPC关系、记忆如何具体影响条件对话或后续事件。
- NPC立绘与场景切换的具体交互方式。
- 正式剧情的具体对话内容和特殊交互细节。

## 3. SYS-003 任务与委托系统

### 任务的目标与类型【已确认】

- **目标明确、解决路径开放**：玩家面对清楚的问题，自主寻找解法；不需要通过反复问询才能知道委托目标。
- 正式委托在表世界**查看、接取、交付**。
- 同一个任务可以通过表世界工程、里世界魔法/环境干预，或二者结合来解决；接取时不必预先选择路径。
- 区分**当日必做任务**和**可选任务**：必做任务影响日期推进，可选任务不阻止日终。
- 可选任务的期限**按任务配置**：允许长期保留、当日限定、剧情/事件条件失效等，不采用统一跨天或统一失效规则。

### 日初发布与主动接取【已确认】

- 每天开始时，向玩家公开**当天全部必做任务及其明确目标**。
- 日初公开**不等于自动接取**。玩家通过对应NPC接待获得正式委托，并**主动点击接受**。
- 玩家可以暂不接取必做任务，但它仍属于当日必做任务集合，不可通过不接取来绕过日终检查。
- 可选任务可以随NPC互动、探索或事件逐步出现，不要求日初全部公开。

###  提前行为有效、多任务共享【已确认】

**TASK-016｜接取前行为有效**

- 玩家在接取前的探索、维修、天气改变等有效操作正常改变游戏状态、留下必要事件记录。
- 正式接取后，任务立即根据当前世界/设施/物品状态及适用的已完成事件记录判断进展。
- 已满足完成条件时可以直接进入「可交付」；不要求重做操作。

**TASK-017｜同一行为可推进多个任务**

- 一个玩家行为可以同时影响多个委托；每个任务独立检查自己的条件。
- 例如一次天气变化可让两项任务同时满足条件，不要求逐个任务重复施法。

###  完成条件与动态判定【已确认】

- 任务可以配置多种有效解决条件，也可以允许组合方案。
- 可检查的条件包括：**环境状态、设施状态、物品持有/交付条件、适用的事件记录**。
- 玩家符合任意一组有效完成条件，即可进入「可交付」。具体条件组合由任务逐项配置。
- **动态判定：** 正式交付前，若原先条件消失且其他有效方案也不再成立，则从「可交付」退回「进行中」。
- 如果一条完成路径失效但另一条仍有效，继续保持「可交付」。
- 任务交付时应再次确认需要的当前状态/物品条件，避免临时天气消失或物品已用完却继续成功结算。
- 普通任务**不强制设置额外验证阶段**；特殊任务是否设置有价值的确认事件按具体内容决定，暂不作为通用首版模块。

**物品条件的两种表现：**

1. **直接交付型：** 玩家在交付时持有指定物品，成功结算时按任务要求消耗。
2. **操作消耗型：** 玩家在制作/维修等设施操作中消耗物品；任务随后判断设施或事件结果，而非要求物品继续留在背包。

### 正式交付与结果反馈【已确认】

- 满足成功条件时只是「可交付」，**不是「已完成」**。
- 玩家必须回到表世界完成正式交付，才进入成功已结算终态；此时处理相应NPC反馈与奖励。
- 不同解决路径的反馈、奖励或世界后果可以**按具体任务配置**；不要求每个普通任务都有多套奖励。
- 可在交付时按玩家实际行动/当前有效条件确定反馈，**不应强制玩家在交付界面再选择一遍解决方案**。（实现建议，具体分支识别方式待技术设计。）
- 混沌变化由关键行为发生时触发，**不因任务交付重复增加**。

### 失败与失败结算【已确认】

- 必做任务**允许失败**；失败可以打开新的剧情/事件线，不意味着游戏卡关。
- 失败条件由每项任务分别配置，可以是**预设剧情/世界事件**，也可以是**玩家不可逆关键行为**。
- 不设所有任务统一的倒计时失败规则；也不要求每个任务一定有失败分支。
- **暂时不满足完成条件不等于失败。** 必须发生已配置的失败条件，才能进入失败流程。
- 触发失败后，任务先进入「失败待结算」，玩家完成对应NPC反馈、事故处理或剧情事件后，进入「失败已结算」。
- 失败反馈不必都是新小游戏；普通任务可用简短对话处理，重要事件可设计更丰富的分支。
- 对于影响日期推进的必做任务，失败反馈必须具备**当天可完成的结算路径**，避免日终无法解锁。
- 成功已结算和失败已结算都是终态；后续世界状态改变不撤销已经结算的任务结果。

### 建议的任务状态【核心含义已确认】

| 状态 | 含义 | 是否满足当日必做任务的日终条件 |
|---|---|---|
| 待接取 | 日初已公开或已出现，但未主动接受 | 否 |
| 进行中 | 已接受，尚未满足当前成功条件 | 否 |
| 可交付 | 当前满足成功条件，但尚未在表世界交付 | 否 |
| 失败待结算 | 已触发明确失败条件，尚需处理后果 | 否 |
| 成功已结算 | 成功交付且完成奖励/反馈结算 | 是 |
| 失败已结算 | 已完成失败反馈及相应结算 | 是 |

其中「进行中 ↔ 可交付」可随环境和其他真实游戏状态动态转换。若接取前发生不可逆失败事件，如何映射到任务状态需在实现时补充边界规则。

###  SYS-003 仍待确认

- 具体任务条件数据的组织形式（AND/OR组合、事件标记与世界状态引用方式）。
- 交付时多条路径同时有效的反馈选择细则。
- 接取前触发失败条件时的状态衔接。
- 各任务具体奖励数值、一次性资源消耗、失败剧情与可选任务期限。

##  SYS-005 每日流程与事件系统

### 时间模型【已确认】

- 游戏采用**按天推进**的结构。
- **一天内部没有持续流逝的游戏时钟**；普通探索、对话、SHIFT不因耗时而推进时间。
- 日间内容以玩家行为、世界状态、任务状态和预设事件条件驱动。
- 玩家自由决定当天NPC接待、探索、设施操作、任务处理的顺序。

### 日初与日间安排【已确认】

- 日初公布当日所有必做任务的**明确目标**；玩家仍须与相应NPC交流并主动正式接取。
- 日初提供大部分**计划来访**信息。
- 可选任务、普通临时来访与剧情入口可以在当天通过预设条件逐步解锁。
- 普通临时来访加入待接待名单，不强制打断当前操作。

###  日终条件与推进方式【已确认】

**DAY-007｜必做任务全部结算才允许结束当天**

- 只有当天全部必做任务进入「成功已结算」或「失败已结算」，才满足日终条件。
- 未接取、进行中、可交付、失败待结算均不满足日终条件。
- 可选任务不阻止结束当天。
- 即使所有必做任务已结算，系统**也不自动推进日期**；玩家可继续探索和交互。

**DAY-009｜日期推进方式按日配置**

| 日期类型 | 结束方式 |
|---|---|
| 普通日期 | 玩家主动点击「结束这一天」按钮 |
| 特殊日期 | 玩家主动访问指定的场景交互或剧情入口，按当天配置结束 |

特殊日期不等于每天都要跑到固定建筑交互。满足日终条件后，按当前日期配置开放对应结束方式。

### 预设事件触发【已确认】

- 初版临时来访和剧情事件**全部采用策划预设条件触发**，不采用概率随机或按交互次数随机抽取。
- 可配置的条件来源包括：日期、任务状态及成功/失败结算结果、NPC状态、场景访问、关键玩家行为、世界环境状态、已发生事件等。
- 事件满足条件后进入待处理状态，**触发剧情解锁条件不等于自动播放剧情**。
- 一次性事件需要记录触发/完成状态，防止意外重复；允许重复发生的事件单独配置。

### 并行开放与玩家主动访问【已确认】

- 同一行为可以同时解锁多个事件；**不设置统一的强制优先级播放顺序**。
- 多个事件分别记录状态，并行处于待处理状态，由玩家自主选择处理先后。
- 普通NPC临时来访进入待接待名单；人物剧情、建筑剧情、双世界场景剧情开放对应NPC/建筑/场景入口。
- **重要剧情也由玩家主动访问才开始**，不因条件满足而强制打断当前对话或设施小玩法。
- 某些事件确有故事前置关系时，可通过配置解锁条件组织依赖，而不是靠全局事件抢占优先级。

### 事件保留与失效【已确认】

- 事件进入待处理状态后，**默认保留，直到玩家完成**；玩家先处理其他事件不使其自动消失。
- 普通待处理事件**默认允许跨天保留**。
- 少数特殊事件可以配置日期截止、特定剧情条件失效或互斥失效；未显式配置则默认长期有效。
- 触发条件与失效条件彼此独立：例如晴天解锁的事件，若未配置因天气改变而失效，就不会因之后下雨而自动清除。

### 建议的事件状态【核心含义已确认】

| 状态 | 含义 |
|---|---|
| 未触发 | 尚未满足预设条件 |
| 待处理 | 已满足条件，入口解锁，等待玩家访问 |
| 进行中 | 玩家已经主动进入对应事件 |
| 已处理 | 内容及结果已结算 |
| 已失效 | 符合事件单独配置的失效条件 |

### SYS-005 仍待确认

- 日期切换时的具体数据更新/清理顺序，以及跨天保持哪些设施与资源状态。
- 具体计划来访的出场时机和NPC可访问性。
- 事件互斥、剧情前置、已打开但尚未完成时退出的细节。
- 环境限时效果与日期推进的精确结合方式。

## 关键系统间流程

### 日常最小闭环【已确认部分】

1. **日初**：显示当天全部必做任务目标及计划来访。
2. **主动接待**：玩家访问表世界NPC，主动接取正式委托；也可以此前先行探索。
3. **自由行动**：在两世界探索、使用设施、改变世界或取得物品。
4. **状态变化**：双世界、设施和资源系统写入真实状态；预设关键行为按事件配置触发混沌。
5. **任务重新判定**：所有关联任务根据当前环境、设施、物品与事件记录更新可交付/进行中状态。
6. **结算**：成功路线回表世界正式交付；失败路线完成相应NPC/剧情反馈。
7. **日终检查**：全部当日必做任务进入成功或失败已结算终态，解锁当日结束操作。
8. **自主结束当天**：按日期配置使用普通按钮或特殊场景交互，进入下一天。

### 测试案例：飞艇稳定性委托

**目标：** 确保飞艇安全通过航线。

- **工程方案：** 在表世界维修飞艇，设施系统更新设备状态。
- **魔法方案：** 在里世界执行改变天气的关键事件，世界联动系统依据配置改变表世界对应天气；事件可能同时增加预设混沌值。
- **组合方案：** 同时维修设备并改善天气，任务可根据实际状态提供不同反馈。
- **先做后接：** 玩家即使先改天气、后接取委托，接取时也检查当前真实状态。
- **动态回退：** 在正式交付前若天气效果结束，且没有其他有效解法，则「可交付」退回「进行中」。
- **同一行为多任务：** 一次天气变化可以同时满足另一项天气相关委托；混沌不因此重复计数。
- **成功结算：** 返回表世界正式交付，得到对应反馈与奖励。
- **失败结算：** 若某个明确配置的失败事件发生，则进入失败待结算，完成后续人物/剧情反馈后进入失败已结算，可能开启后续事件线。

### 主要数据流

| 数据/信号 | 产生方 | 使用方 |
|---|---|---|
| 当前世界、玩家对应位置 | 双世界系统 | 场景、NPC表现、设施入口 |
| 环境状态变化 | 双世界/事件系统 | 任务判定、场景表现、事件条件 |
| 设施操作结果 | 设施系统 | 任务判定、资源、事件条件 |
| 物品与资源数量 | 资源/设施系统 | 任务交付、制作/维修 |
| 任务状态与结算结果 | 任务系统 | NPC反馈、事件触发、日终检查 |
| NPC来访/对话状态 | NPC与事件系统 | 接待入口、任务发布 |
| 事件待处理/已处理 | 事件系统 | NPC/场景交互入口、剧情依赖 |
| 混沌变化触发 | 关键预设事件 | 混沌系统 |

##  第一轮开发范围与验收建议

> 本节为**实施建议**，不是新增的玩法确认事项。

### 建议优先实现的底层能力

1. 当前世界记录、双向SHIFT、对应位置切换，以及受小玩法状态约束的SHIFT入口。
2. 双世界基础环境属性与预设事件修改机制；一次天气跨界联动。
3. NPC双身份数据、基础对话、对话中的SHIFT提示与视觉切换。
4. 日初必做任务清单、主动接取、动态完成条件、成功/失败结算。
5. 事件触发记录、多个事件并行待处理、玩家主动访问入口。
6. 日终检查与按日期配置的主动结束方式。

### 建议的最小可玩测试日

- 当天出现一项有**两条有效解决路径**的必做委托。
- 玩家可以先探索后接取，也可以先接取后探索。
- 玩家能在两个世界间自由切换，并通过一个预设事件改变对应环境。
- 关键事件混沌结算只发生一次；任务状态会因环境状态变化动态更新。
- 玩家可以在表世界成功交付；测试配置也能验证失败待结算→失败已结算。
- 两个独立的待处理事件可以并行解锁，玩家自选先后访问。
- 全部当日必做任务结算后，由玩家主动结束当天并进入下一日。

### 必须进行的交叉检查

- **地图：** 可SHIFT位置在两世界都可合法落脚。
- **对话：** SHIFT确认后只换场景/立绘，不破坏当前文本、选项、进度。
- **小玩法：** 隐藏SHIFT时快捷键同样无效；退出后恢复。
- **环境效果：** 新效果覆盖旧效果；已覆盖的临时效果不会过期后反写当前状态。
- **任务：** 接取前行为有效；一个行为影响多个任务；状态条件失效能回退；物品不能重复消耗。
- **结算：** 成功必须正式交付，失败必须完成反馈；二者均可满足当日必做结算要求。
- **事件：** 多事件同触发不丢失、不强制依次播放；默认保留，专门配置才失效。
- **日期：** 日终条件满足后不自动换天；普通/特殊日期各按配置推进。

## 跨系统待定事项与分工边界

### 必须在具体功能落地前补充

- **设施系统（交由其他策划）：** 各设施输入、操作、资源消耗、输出状态、可触发事件，以及与任务判定的接口。须遵守“设施场景可SHIFT、小玩法中禁用SHIFT”。
- **资源系统：** 物品持有、消耗、来源及交付接口；经济数值尚未确定。
- **混沌系统：** 关键事件混沌增量及其后续效果；已确认的触发方式不可改成“每次SHIFT增加”。
- **具体任务与剧情：** 每项委托的有效条件、奖励、失败条件、结算反馈与可选任务有效期。
- **事件内容：** 每个事件的触发条件、入口、保留/失效、前置依赖和结果。

- 设施专属小玩法的具体交互、流程和UI布局。

- 各类环境限时效果的精确计量单位。
- 各天必做任务的具体数量、NPC完整名单、正式任务文案。
- 特殊日期使用哪个具体场景交互对象结束当天。
- 复杂人物关系数值、随机来访机制和实时日内计时。

## 版本变更与冲突清理记录

本稿以**最新确认规则**覆盖历史讨论中的以下方向：

| 被替代的早期表述 | 当前应采用的规则 |
|---|---|
| 核心体验优先经营调度 | 核心体验优先交互体验 |
| NPC普遍需要需求推理 | 任务目标明确，少量特殊内容可推理；重心在解法探索 |
| SHIFT切换本身增加混沌 | SHIFT自由切换且不增混沌；重大跨世界影响事件才按预设配置增加 |
| SHIFT到无法站立位置后搜索附近落点 | 地图设计直接保证对应位置可落脚 |
| 设施内任何操作都直接切换对应设施界面 | 设施场景能切换；小玩法操作中隐藏并禁用SHIFT |
| 全部任务必须当天完成 | 仅当日必做任务必须当天**结算**；可选任务期限按任务设置 |
| 必做任务必须成功才能日终 | 成功已结算或失败已结算均可计入日终 |
| 重要剧情自动打断当前操作 | 达成条件后解锁入口，玩家主动访问 |
| 事件严格排队播放 | 多事件并行待处理，由玩家选择顺序 |
| 每天固定到站房特定物件结束 | 常规按钮或特殊场景交互，按日期配置 |
| 实时时钟推动NPC和临时事件 | 无实时日内时钟，临时事件由预设条件触发 |
